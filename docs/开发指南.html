1. 软件总览与文件地图

GitNow 是一个终端里的 Git 面板：左边看文件改动并暂存，右边看 diff 和历史，按键完成提交 / push / pull。 所有 Git 操作都是直接调用 git 命令行（子进程），不依赖任何 Git 库。

+------------------------+--------------------------------+
| 文件树 (左上)            |  右侧视图（三态）               |
|  改动+新增文件, t 切全部  |   选中文件  -> 该文件 diff      |
|  目录折叠, 状态色标       |   无选中    -> git log 列表     |
+------------------------+   log 按 Enter -> 提交详情      |
| 已暂存 staged (左下)     |                               |
+------------------------+-------------------------------+
| 状态栏: 分支 | ahead/behind | 计数 | 键位条                |
+-------------------------------------------------------+

外观规则（gitlogue 风格）：每个面板是一块暗色色块，面板之间不画线框； 只有持有焦点的面板才出现一圈彩色圆角边框。实现技巧见 4.3 节。

2. 整体设计逻辑

2.1 三层架构

┌─────────────────────────────────────────────────────┐
│ UI 层   app.py + panels/*                            │
│         只做三件事：显示数据、接按键、发消息            │
├─────────────────────────────────────────────────────┤
│ 数据层  models.py（纯数据，无行为）                    │
│         FileEntry(xy 状态码) LogEntry RepoStatus      │
├─────────────────────────────────────────────────────┤
│ git 层  gitbackend.py（唯一出口）                     │
│         每个函数 = 启动一个 git 子进程 + 解析输出       │
└─────────────────────────────────────────────────────┘
规则：UI 层永远不直接 subprocess，git 层永远不 import UI 层。
     想换 UI 框架，只重写 UI 层；想加 git 功能，只动 git 层 + 一个按键。

2.2 三个核心设计，理解了它们就读懂了 app.py

① 单一刷新入口。任何会改变仓库状态的操作（暂存、提交、push…）结束后都走 refresh_all()：它重新执行 git status，重建左边的两个面板， 并尽量保持你当前选中的文件不变。UI 上你看到的一切列表，都是 status 解析结果的投影—— 面板自己不存状态，所以不会出现"界面和 git 实际状态不一致"。

② 选择（selection）驱动右侧。App 里只有一个 self.selected = (面板名, 路径) 决定右侧显示什么： None → 显示 log；有值 → 显示该文件 diff（从哪个面板选的就看哪种 diff）。 左面板光标一动 → 发消息 → App 更新 selected → 后台取 diff → 回填。

③ token 防串台。取 diff 是后台线程，用户光标可能在你取完之前又动了。 所以发起请求时记一个 token，结果回来先比对 token，不一致就丢弃—— 保证右侧永远是"当前选中"的内容，而不是"最先发出请求"的内容。

2.3 右侧视图状态机

            ┌─────────────────────────────────────────┐
            │  viewer.mode:  "log" ⇄ "diff" ⇄ "commit" │
            └─────────────────────────────────────────┘
 log ──选中文件──> diff          diff ──Esc/文件消失──> log
 log ──Enter──> commit           commit ──Esc──> log
 位置：log 显示在 LogList(OptionList)，diff/commit 显示在 Static，两者靠 display 切换互斥

3.2 刷新流程（所有读操作的汇聚点）

refresh_all()  装饰器 @work(thread=True, group="refresh", exclusive=True)
├─ [后台线程] gitbackend.status(repo)      git status --porcelain=v2 --branch -z -uall
├─ [后台线程] (仅 all 模式) list_all_files  git ls-files -z --cached --others --exclude-standard
└─ call_from_thread(_apply_status, st, all_files)   ← 切回 UI 线程才能碰界面
   _apply_status():
   ├─ self.status = st
   ├─ status_bar.update_status(st)         分支/箭头/计数
   ├─ tree_panel.rebuild(st, ..., keep=current_path)   重建树，光标回到原文件
   ├─ staged_panel.rebuild(st, keep=...)
   └─ 选中校验：selected 的文件不再有改动?
        └─ 是 → selected=None, viewer 回退显示 log
为什么要 call_from_thread？Textual 的界面只能在主（UI）线程里改。 git 子进程要几百毫秒，直接在按键处理里跑会卡住整个界面，所以放后台线程， 跑完把"结果"递回 UI 线程去刷新。这是本项目所有 git 调用的固定套路。

3.3 选中文件 → 右侧显示 diff

用户按 j/k / ↑↓
└─ Textual 检测到 Tree 光标行变化 → 发出 Tree.NodeHighlighted 事件
   └─ FileTreePanel._node_highlighted (panels/tree.py)
      ├─ 记录 self.highlighted_path
      └─ if self.has_focus: post_message(FileHighlighted("tree", path))
          │                ← 没焦点的面板不发，防止后台刷新抢走右侧视图
          └─ 消息沿组件树冒泡 → GitNowApp.@on(FileHighlighted)
             └─ set_selection(panel, path) (app.py L167)
                ├─ 和上次相同? → return（去重）
                ├─ self.selected = (panel, path)
                ├─ viewer.token = (panel, path)      ← 记 token
                └─ request_diff()  @work(thread, group="diff", exclusive)
                   ├─ [线程] 按 entry 状态挑命令：
                   │    staged 面板来的       → git diff --cached
                   │    未跟踪文件             → git diff --no-index /dev/null
                   │    其他                   → git diff（工作区）
                   └─ call_from_thread(viewer.apply_diff, path, badge, text, token)
                      └─ viewer: token 不一致 → 丢弃；一致 → 上色渲染

3.4 按 Space 暂存（所有"写操作"的模板）

FileTreePanel BINDINGS: Binding("space", "stage_toggle")
└─ action_stage_toggle() → app.stage_toggle("tree", path)
   └─ 查 status: 有工作区改动 → stage_paths；只有暂存区改动 → unstage_paths
      └─ _mutate(gitbackend.stage, (paths,), "暂存 N 个文件")   (app.py L296)
         ├─ _busy += 1，状态栏显示 "…"
         └─ _run_mutation  @work(thread, group="mutate")
            ├─ [线程] fn(repo, *args)  →  git add -- :(literal)path
            │    GitError → 捕获，stderr 存入 error
            └─ call_from_thread(_mutation_done, desc, detail, error)
               ├─ _busy -= 1
               ├─ notify(...)   成功/失败 toast（git stderr 原样展示）
               ├─ refresh_all() ← 统一刷新
               └─ load_log()    ← log 可能变了（比如刚提交过）
想加任何新的"写仓库"操作（stash、ignore…），照 3.4 的模子： gitbackend 加一个函数 → app 里 _mutate(gitbackend.xxx, (参数,), "描述") → 面板加按键。 三步，完事。

3.6 push / pull

P → action_push ─ 没提交过? notify 警告 ─ _mutate(gitbackend.push, (分支名,), "push")
p → action_pull ─────────────────────── _mutate(gitbackend.pull, (), "pull")

4. Textual 新手课 —— 本项目用到的 10 个概念

每个概念按 是什么 → 本项目哪里在用 → 最小例子 讲。看完这章就能看懂第 5 章的逐文件精读。

4.1 App 类与 compose：搭界面的地方

Textual 程序 = 一个继承 App 的类。compose() 方法里"声明"界面长什么样： yield 组件就是放组件，with 容器: 就是开一个子区域。容器也是组件 （Horizontal 横排、Vertical 竖排），用 id= 起名字，CSS 靠名字选中它。

class GitNowApp(App):
    TITLE = "GitNow"
    CSS_PATH = "gitnow.tcss"          # 样式文件（相对本文件）

    def compose(self):                       # app.py L57
        with Horizontal(id="main"):          # 整屏横排容器
            with Vertical(id="left"):        # 左列（竖排）
                yield FileTreePanel(id="tree-panel")    # 左上
                yield StagedPanel(id="staged-panel")    # 左下
            yield RightViewer(id="viewer")               # 右侧
        yield StatusBar(id="statusbar")      # 底部（dock: bottom 钉在最下）

之后任何地方都能用 self.query_one("#tree-panel", FileTreePanel) 拿到这个组件的引用 （本项目把它们包成了 tree_panel 等 property，见 app.py L65-84）。

4.2 CSS：色块 + 只有焦点才有边框

Textual 的 CSS 和网页 CSS 很像：选择器可以是 #id、组件的 Python 类名（如 FileTreePanel）、伪类 :focus。文件在 CSS_PATH 指向的 gitnow.tcss，改样式只动这一个文件。

/* 左上：文件树 —— 一块深灰蓝色 */
FileTreePanel {
    height: 62%;            /* 占左列 62% 高，其余给下面的 staged */
    background: #151c28;    /* 这就是"色块" */
    border: round #151c28;  /* 关键技巧：边框颜色 = 背景色 → 看不见，但占着位置 */
    padding: 0 1;
}
FileTreePanel:focus { border: round #7aa2f7; }  /* 拿到焦点 → 换成亮蓝色圆角框 */
为什么边框一直存在只是"隐身"？如果焦点切换时才加边框，边框会挤压内容区导致整屏跳动。 让未聚焦面板的边框颜色等于背景色，就同时做到了"看起来无线框"和"聚焦时不跳动"。 改主题颜色时请保留这个套路。

4.3 BINDINGS 与 action_ 命名约定

给组件（或 App）定义类属性 BINDINGS 就能接按键。Binding(键, 动作名) 里的动作名会自动映射到同名 action_动作名 方法：

Binding("space", "stage_toggle")     # 按 Space → 自动调用 action_stage_toggle()
Binding("P", "push")                 # 大小写敏感：P 是 Shift+p，和 p 是两个键
Binding("j", "cursor_down", show=False)  # show=False: 不出现在底部键位条

按键的查找顺序：当前焦点组件 → 它的父组件链 → 当前 Screen → App。 所以同一颗 a：焦点在文件树时走 FileTreePanel 的绑定，焦点在别处走 App 的 action_stage_all——两条路殊途同归（都调 app.stage_all）。

TextArea（提交输入框）会先消费所有字符键。所以在提交弹窗里打字不会触发 App 的 c/p 等全局键——这是特性不是 bug，全局键只在没有组件消费时才轮到 App。

4.4 自定义消息：面板向 App 汇报

面板不该直接操作别的面板，而是发消息让 App 决定。三步：

# ① 定义消息类（panels/tree.py）
class FileHighlighted(Message):
    def __init__(self, panel: str, path: str):
        self.panel = panel; self.path = path
        super().__init__()               # 必须调用

# ② 面板里发出（消息会自动向上冒泡到 App）
self.post_message(FileHighlighted("tree", path))

# ③ App 里用 @on 接（app.py L163）
@on(FileHighlighted)
def on_file_highlighted(self, event):
    self.set_selection(event.panel, event.path)

相关细节：event.stop() 可以阻止消息继续冒泡（viewer 的 LogNearEnd 就这么干的）； 消息类名决定处理器查找名，用 @on(消息类) 最省心。

4.5 reactive 属性：赋值即生效

Textual 组件的一些属性是"响应式"的：赋值会自动触发重绘和事件。 本项目用到的：OptionList.highlighted（当前高亮行号）、Tree.cursor_line、 Tree.show_root。比如选中列表某行只需 panel.highlighted = 3， 且这一下会触发 OptionHighlighted 事件——和用户按键完全一样。

第 3 版调试时发现：set_options() 之后 highlighted 是 None （不是 0），所有读它的逻辑静默失效——包括"按 Enter 查看提交"。所以本项目每次重建列表后都显式 highlighted = 0。你写新面板时记得同样的坑。

4.6 @work 后台线程 + call_from_thread

@work(thread=True, group="diff", exclusive=True)   # app.py L174
def request_diff(self):
    text = gitbackend.diff_worktree(...)            # 线程里跑 git，UI 不卡
    self.call_from_thread(self.viewer.apply_diff,   # 回 UI 线程改界面
                          path, badge, text, token)
  • thread=True：在后台线程执行（git 子进程会阻塞几百毫秒）。
  • group + exclusive=True：同组的新请求会把还没跑完的旧请求作废——光标连按时只取最后一次。
  • call_from_thread：后台线程里唯一合法的"碰界面"方式。
  • token 比对：见 2.2 ③。

4.7 on_mount / set_interval：启动与定时

on_mount 在界面挂载完成后执行一次，适合做初始化（本项目：设标题、发首批请求、起定时器、设焦点）。 self.set_interval(3.0, 回调) 每 3 秒调用一次回调（自动刷新， 回调里会跳过"正在忙 / 弹窗打开"两种情况，app.py L98）。

4.8 弹窗：ModalScreen + dismiss + callback

App 侧:  self.push_screen(CommitModal(数量), 回调函数)     # app.py L330
弹窗侧:  self.dismiss(message)    # 关闭自己，message 作为返回值传给回调
                                  # dismiss(None) 表示取消

弹窗是独立 Screen（len(self.screen_stack) > 1 可以判断"现在有弹窗吗"， 自动刷新就是靠这个在弹窗期间暂停的）。弹窗自身也有 BINDINGS：Ctrl+S 提交、Esc 取消。

4.9 notify：右上角 toast

self.notify("文本", severity="error", timeout=10, markup=False)。 凡是拼接了 git 输出/文件路径的文案，务必 markup=False—— 否则内容里的 [ 会被当成富文本标记解析报错。

4.10 富文本 Text：给文字上色

列表行、diff 都是 rich 的 Text 对象：纯文字用 Text("abc", style="#565f89")，一行多色用 Text.assemble(("M ", "bold red"), ("文件名", "#c0caf5"))。 本项目所有颜色常量集中在 theme.py。Static 组件用 static.update(Text对象) 整体刷新内容。

5. 逐文件精读

5.1 gitnow/__main__.py —— 入口（20 行）

解析命令行参数（可选仓库路径，默认当前目录）→ 校验是 git 仓库 → 才 import 并运行 App。 App 的 import 放在校验之后是故意的：报错路径不需要加载 Textual，启动更快、打包验证也更干净。

5.2 gitnow/models.py —— 数据结构（100 行）

核心是 FileEntry：一个文件 = 一个两位状态码 xy （来自 git status --porcelain=v2）。读懂 xy 就读懂了整个状态系统：

xy含义树面板显示暂存面板显示
M.只改了工作区，未暂存橙 M不显示
.M不可能出现（.M 表示只改了 index）——
M. 之前已 add → MM暂存后又改橙 M（树里仍在）绿 M
??未跟踪（新文件）蓝 ?不显示（add 后变 A.）
A.新文件已暂存不显示（工作区无改动）绿 A
D. / .D删除（已暂存/未暂存）红 D红 D
UU 等合并冲突亮红 UU亮红 U

四个派生属性是全项目的判断依据：has_index_changes（xy[0]≠. 且非未跟踪）、 has_wt_changes（未跟踪或 xy[1]≠.）。未跟踪文件要特判：它的 xy 是 "??"， 按字符判断会误报"有暂存改动"——这是修过的真实 bug。

RepoStatus 持有分支信息 + 全部 FileEntry，提供 entry(path) 查单个文件、worktree_entries / index_entries 两个过滤视图、 signature（供比对的指纹）。

5.3 gitnow/gitbackend.py —— git 唯一出口（280 行）

所有函数都是"拼参数 → 子进程 → 解析字符串"三段式。全项目只有这里出现 subprocess。

def git(*args, cwd, allow_fail=False, timeout=60):
    cmd = ["git",
           "-c", "core.quotepath=false",   # 中文文件名不转义
           "-c", "core.pager=cat",          # 禁止分页器（否则挂死）
           "-c", "color.ui=false",          # 不要 ANSI 颜色码，纯文本好解析
           *args]
    proc = subprocess.run(cmd, cwd=str(cwd), env=_base_env(),
                          capture_output=True, text=True,
                          encoding="utf-8", errors="replace")
    if proc.returncode != 0 and not allow_fail:
        raise GitError(args, proc.returncode, proc.stderr)
    return proc

常用函数与命令对照（完整表见附录 B）：

status()      git status --porcelain=v2 --branch -z --untracked-files=all
              # -z: NUL 分隔，文件名带空格/中文都安全

5.4 gitnow/panels/tree.py —— 左上文件树（范例精读）

这是最典型的一个面板，其他面板全是同一套模式：子类化一个 Textual 组件 → 类属性 BINDINGS → rebuild() 重建内容 → 高亮事件向外汇报 → action_ 方法调 app。

class FileTreePanel(Tree):                 # 继承 Textual 的树组件
    BINDINGS = [
        Binding("space", "stage_toggle", "暂存/取消", show=True),  # show=True → 上键位条
        Binding("a", "stage_all", ...),  Binding("u", "unstage_all", ...),
        Binding("d", "discard", ...),    Binding("e", "edit", ...),
        Binding("t", "toggle_mode", ...),
        Binding("j", "cursor_down", show=False),   # vim 键，不占键位条
        Binding("k", "cursor_up",   show=False),
    ]

    def __init__(self, **kwargs):
        super().__init__("files", **kwargs)
        self.show_root = False        # 隐藏根节点（注意：是属性，不是构造参数）
        self.mode = "changes"         # changes=只看改动 / all=全部文件
        self._file_nodes = {}         # path -> TreeNode，重建后 O(1) 找回光标

    def rebuild(self, st, all_files, mode, keep_path):
        self.clear()                                  # 清空旧树（保留根）
        path_map = 改动文件字典 或 全部文件字典
        nested = 嵌套字典                                # "src/c.txt" → {"src/": {"c.txt": ...}}
        self._build_tree(self.root, nested, path_map)  # 递归建节点，目录在前
        # 重建后找回光标：优先 keep_path（App 传来的当前选中），否则第一个文件
        if target in self._file_nodes:
            self.select_node(node)                     # 设光标（会触发 NodeHighlighted）
            self.scroll_to_node(node, animate=False)

    def _label(self, name, entry):                     # 每行的富文本：状态字母 + 文件名
        letter = entry.wt_letter                       # M / D / ? ...
        color = theme.WT_COLORS[letter]
        return Text.assemble((f"{letter} ", f"bold {color}"), (name, theme.FG))

    @on(Tree.NodeHighlighted)                          # 光标落在某行 → 汇报给 App
    def _node_highlighted(self, event):
        if data.get("path") and self.has_focus:        # 目录行没有 path；无焦点不发
            self.post_message(FileHighlighted("tree", data["path"]))

    def on_focus(self):                                # 拿到焦点时补发一次当前选中
        if self.highlighted_path:
            self.post_message(FileHighlighted("tree", self.highlighted_path))

    def action_stage_toggle(self):                     # Space → 调 app 的统一入口
        path = self._cursor_file()
        if path: self.app.stage_toggle("tree", path)
血泪坑：子类方法名不能和基类内部方法撞名。第一版把建树方法命名为 _build，恰好是 Tree 内部的建行方法，结果 Textual 内部 watcher 调它时报"缺参数"， 错误出现在 compose——离真正原因十万八千里。给子类写私有方法前先 dir(基类) 查一下， 或统一加前缀（如 _build_tree）。
